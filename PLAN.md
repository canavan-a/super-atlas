# Plan: Open Location → Super Atlas

Rename the app to **super-atlas** and give it the same look as `../super-chat`
and `../super-badger`: five switchable themes, the pixel-art logo and splash,
and a launcher icon that follows the theme.

**Approach:** keep Expo + CNG and port the look, rather than re-platforming to
bare React Native like the siblings. Re-platforming would mean rewriting
background location, permissions and secure storage to match a web target this
app can't really use. The one Expo-specific cost is the native icon switcher,
which has to go in through a config plugin because `app/android` is gitignored
and regenerated by `expo prebuild`.

**Estimate:** ~3–4 days for Phases 1–4, ~1 day for invite links (Phase 5).

---

## Phase 0 — Decisions

- [ ] Android package: `com.open_location` → `com.superatlasapp`. A new package
      is a new app, so existing installs won't upgrade in place.
- [ ] Default theme: `dark` (super-chat) or `light` (super-badger).
- [ ] Server module path: `github.com/canavan-a/super-atlas/server`, or
      `module main` like the siblings.
- [ ] Builds: keep EAS, or add a sibling-style `release/` sideload pipeline.

- [ ] Replace every `colors.x` use (~85, in 7 files) with `useTheme()`: static

## Phase 5 — Invite links (optional, ~1 day)

There are no invite links today: friends are added only by exact email via
`POST /friends` (`server/internal/friends/handlers.go:44`). Model these on
super-chat's links (expiry, use limit, revocable).

- [ ] Server:
  - [ ] Migration `0004_invites.sql`: `friend_invites (id, inviter_id,
        token_hash, expires_at, max_uses, uses, revoked_at)`.
  - [ ] `POST /invites`, `GET /invites`, `DELETE /invites/{id}`,
        `POST /invites/{token}/accept` (creates an already-accepted
        friendship).
  - [ ] Rate-limit the accept endpoint.
- [ ] App:
  - [ ] `superatlas://invite/<token>` scheme in `app.json` (https App Links
        also need a hosted `assetlinks.json`).
  - [ ] "Invite a friend" share-sheet action on the Friends screen.
  - [ ] Deep-link handling: if signed out, stash the token, go through
        signup/login, then accept automatically.
- [ ] Side benefit: no need to know a friend's email, which closes most of the
      email-enumeration gap on signup.
